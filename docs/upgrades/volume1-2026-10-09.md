Candidate preparation only. Shipping MGSHDFix 4.1.0, MGSM2Fix v3.6,
MGS2 Bugfix 3.0.0 and MGS3 Bugfix 2.0.1 remain unchanged. The actual
MGS2/MGS3 Config Tool exports are absent; adoption is blocked.

## Source and release review

`volume1-candidate.json` records official release URLs/IDs, literal commits,
GitHub signature status, asset IDs, SHA256s, complete ZIP layouts and selected
payload hashes. Official Git tag resolutions agree with the API commits.
Repository identity and immutable byte comparison are the authentication used;
unsigned commits are recorded honestly, without claiming author signatures or
reproducible binary builds. Only base Bugfix ZIPs are included.

Preview/nightly releases and upscaled addons are excluded. MGSM2Fix 3.6.0 and
3.7.3 have byte-identical `MGSM2Fix.ini` files and the same seven-member layout;
binary identity differs. Preserve all supported user INI values rather than
resetting them when adopting it later.
The packaged INI uses CRLF and its authenticated Git source blob uses LF;
normalizing that explicit line-ending difference gives identical content.

MGSHDFix 4.1.2 source captures 27 sections / 134 fields, matching the union of
139 runtime read calls (including conditional calls). Capture is bounded to the
hashed reviewed files. `ConfigTool/main.cpp` creates hidden controls and saves
the entire control map: MG-only fields remain required. Save-time language
resolution and dynamic controls mean static defaults are not native exports.
The `MGS3_FPS_DEV` flag union is not evidence of release FPS support.

## Migration disposition for adoption

Relative to repaired 4.1.0, `Bugfixes` gains `Fix Dropped Item Toss`,
`Fix Emissive Textures`, and `Fix Lighting Bounding Boxes` (boolean fields).
`Model Quality && Level of Detail Enhancements/Show Soft Particles` is renamed
to `Blend Particle Effect Sprites` under the same ConfigKeys identifier.
Its static UI default also changes from true to false. Preserve a user's
existing value through the rename; do not apply the new default to repaired
installs. Actual fresh defaults remain subject to native capture.

After exports: normalize only the recognized complete legacy 128-key shape
using the existing three-field repair and pressure-overlay correction; migrate
the complete repaired 131-key shape by explicit rename plus exported new
defaults. Refuse partial shapes, unknown keys, conflicting old/new names and
malformed values before writes. Test custom language/render/hotkey values,
selected option changes, preview without writes, cancellation/rollback and
original backup lineage. None of this candidate migration ships in this batch.

Upstream asks upgraders to remove `d3d11.dll`. Removal must require an existing
kit ownership record plus matching recorded installed bytes, and preserve the
original backup/recovery lineage. An untracked loader or modified owned file
must remain untouched and produce a reviewable conflict. No loader removal is
implemented here; Worker A retains transaction/engine ownership.

## Repeat the independent checks

Download each exact `assets[].url` in the manifest into a scratch directory.
Do not extract candidates over live games. Authenticate the official releases
and tags again if assets or refs drift; do not silently refresh manifest hashes.

```sh
git clone https://github.com/ShizCalev/MGSHDFix.git scratch/MGSHDFix
git -C scratch/MGSHDFix checkout --detach 33e80bf4d2223f6866b0b92e06c3c9b85efab652
git -C scratch/MGSHDFix ls-remote origin refs/tags/4.1.2
python3 tools/validate_volume1_candidate.py --source scratch/MGSHDFix --archives scratch/archives
python3 tools/validate_volume1_candidate.py --capture-template > scratch/capture.json
```

The archive check hashes full ZIP bytes, compares exact member layouts, checks
CRCs and hashes executable/INI/loader payloads without extracting. Source check
compares tag/HEAD and audited bytes with the literal commit before recapturing
canonical and runtime fields. It is not a general C++ parser or native install.
MGSHDFix's committed `.gitattributes` requests CRLF C++ checkouts. The manifest
records checkout hashes and Git blob hashes separately, permitting only that
exact LF-to-CRLF conversion while authenticating the attributes file too.

## Native Worker handoff

On Windows use `py -3` if needed; on Deck use the game's Proton environment.
Use disposable copies of licensed MGS2 and MGS3 directories with the appropriate
executables. Preserve existing settings, saves and originals outside the capture
copies. Use exactly the manifest's MGSHDFix ZIP; record archive and Config Tool
EXE hashes. Record OS/Proton version, capture UTC, operator identifier, game
versions and procedure without personal filesystem/account paths.

For each game separately, start with no settings file. Run the actual packaged
Config Tool in that game's copy and Save and Exit. Keep untouched CRLF bytes as
`mgs2-default.settings` / `mgs3-default.settings`. Reopen; record dynamic region,
language and controller lists, hotkey representation, float bounds/defaults and
dependent/hidden controls with screenshots or timestamped UI observations.
Do not manufacture hidden values from source. Note controls that are invisible.

Apply documented kit choices in the actual UI: Xbox buttons on Windows or
Steam Deck buttons on Deck, stereo, launcher and splash skips, update checks
off. Keep gameplay/FPS additions disabled. HQ cutscenes are an official launcher
preference: capture separately; do not invent a corresponding MGSHDFix key.
Save as each game's `*-kit.settings`. Record any choice the UI cannot express.

Generate the blank `capture.json` form with `--capture-template`; fill all
provenance fields, four file SHA256s and per-game `dynamic_fields` values,
available choice lists and evidence references. Values are normalized JSON
strings/numbers matching the exports. Put the form, four files and observation
evidence together. Run:

```sh
python3 tools/validate_volume1_candidate.py --exports scratch/capture
```

Deliver that complete bundle and command output/exit code to Brain for native
provenance/default review and Worker B adoption. Structural validation cannot
prove that declared provenance is truthful or kit defaults are correct.
Native game boot, repair and removal, including real recovery/audio behavior,
remain separate release evidence even after exports validate.
